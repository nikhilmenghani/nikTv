# NikTV UI conventions

- Follow NikTV's existing visual design when adding or changing screens. Reuse `NikColors`, existing action buttons, glass surfaces, rounded shapes, and remote focus frames.
- Keep layouts compact: restrained headings, small gaps, and controls sized for their content. Avoid oversized cards, excessive empty space, and expanding secondary actions inline.
- Keep the current profile tiles visible together on ordinary phone and tablet layouts. Allow scrolling for larger profile collections and small windows.
- Preserve the established Home artwork, hero fading, and navigation styling unless the task explicitly changes them.
- Support touch, accessibility, keyboard, and TV remote navigation. Check relevant UI changes on phone and tablet; keep distinct actions as separate, reachable targets.
- Match press, hold, and focus feedback to the target's shape and bounds. Avatar tile feedback uses the avatar's rounded shape and must not cast a rectangular overlay behind its separate name label.
- On tablet/TV and mobile-landscape headers, keep the profile button with its clock on the right. Portal choices belong in a compact glass popup below the profile button, alongside a Switch profile action. Do not reserve header space for portal buttons or resize the menu when the popup opens. Preserve the mobile portrait header unless explicitly changing it.
- Storage belongs in Settings → Library & backup, with files scoped by viewing profile and portal. Label shared app caches separately, measure allocated torrent bytes, and preserve active stream leases during cleanup. My List and Downloads navigation must not expose a separate Storage tab.
- Network requests, sync merges, and storage decoding must not run on the UI thread or block navigation. Show quiet progress and recovery status using the existing visual language.

- Apply shared tablet/TV UI changes to mobile landscape as well, with compact proportions for short windows. Verify the production navigation entry path in portrait and landscape; testing an isolated component alone does not verify that the app opens it.

- Before completing any new or changed screen, validate D-pad focus on the real controls (tabs, buttons, fields, menus and tiles). The focus border must match the visible object's exact bounds, corner radius and shape, with a single outline and no clipping, detached rings, duplicate borders or layout shifts. Check selected and unselected states, short and long labels, first/last items, and return from popups on tablet plus relevant TV/mobile-landscape layouts. Use screenshots to compare focused and unfocused geometry.

## Focus transitions are part of the UI contract

- A correct final focus destination is insufficient: no intermediate control may visibly acquire focus during opening, closing, loading, sorting, selection, IME dismissal or navigation. In particular, never let focus fall back to the page's Back/Home/first item before restoring its intended target.
- Prefer stable, continuously mounted focus targets and stable lazy-item keys. Transfer focus to the surviving target before removing/replacing a focused editor, tile or popup trigger. Do not use clearFocus(), arbitrary delays, repeated late requestFocus() calls or a page-wide focus reset as the primary solution for a visible jump. Diagnose the component lifecycle and focus owner first. Popup entry may wait for attachment/window readiness, but must not fight subsequent user navigation.
- Search activation by touch or D-pad OK opens the editor and IME together; directional focus alone never opens the IME. First Back dismisses the active search and keyboard together and retains focus on Search; subsequent Back performs normal navigation. A season picker opens with the selected season focused and visible; closing a popup returns directly to its originating control. Preserve the originating episode and viewport across menus and data changes.
- Implement these behaviors in shared controls/helpers used by IPTV and TMDB, tablet/TV and mobile landscape. Fix the shared cause rather than patching each screen with independent timers. Do not broaden changes to unrelated UI.
- Focus chrome must use the exact same shape and bounds as its visible control, including clipping, indication, background, border and shadow. Reuse one shape definition across these layers. Do not apply rectangular focus/press shadows to a rounded child or to a wrapper that includes labels/gaps. Reserve border space so focusing never changes layout; show one focus outline.
- Read composition locals unconditionally before calculating focus-dependent button styling. Pass pure color, border and sizing values into the control; conditional composable reads inside its arguments can change generated composition groups and replace the focused layout node. When an outer composable survives but its focus target detaches on redraw, inspect this grouping before adding restoration requests or timers.
- For a recurring focus bug, add or extend a targeted device regression covering the transition itself, including IME/window handoff and touch-to-D-pad switching. End-state-only assertions cannot establish that a jump is fixed; use focus-event history or a short recording/frame inspection to detect intermediate focus. Check focused/unfocused screenshots for shape regressions. Run only the affected scenarios; avoid a full suite/build matrix for every visual tweak.
- Device checks must use fresh UI observations and stop dependent actions when a target/action fails. Do not continue a scripted key sequence against an unexpected page. Report build success, final-focus assertions and visual transition verification separately; never claim a flash-free transition based only on the final screenshot or accessibility snapshot.
- For release-only startup or UI crashes, verify the affected saved-profile/portal entry with the minified release, not just Debug. `-PreleaseSmokeBuild=true` builds the release under the Dev package and debug signing in `app/build-release-smoke`; include `-PfireTvApk=true` for Fire TV. Preserve stable app data, retain R8 mapping artifacts, and inspect launch logs after entering the affected route.
